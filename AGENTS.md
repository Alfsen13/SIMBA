# SIMBA — Agent Guidance

Laravel 13 LMS with AI (RAG tutor, kuis/tugas/remedial, risk scoring + RF, pendidikan/pendaftaran). **29 migrations**, **36 models**, **42 controllers** (41 Web + 1 Api), **28 services** (24 + 4 in `Tugas/`), **11 jobs**, **8 commands**, **6 notifications + NotifikasiChannel**, **5 observers** (3 empty), **7 policies** (1 unregistered), **130 Blade views**, **73 tests** (61 Feature, 12 Unit). No repo layer. **Git repo** (branch `main`, remote `origin`).

## Commands

## Critical Gotchas

- **Tests + caches:** With `config:cache`, tests may hit real MySQL and `RefreshDatabase` wipes data; route cache hides new routes. `composer test` clears optimizations first. `view:cache` alone is OK.
- **Serving:** FrankenPHP on port 8000 (PHP 8.3+). Apache/XAMPP won't run it; CLI PHP may differ from FrankenPHP.
- **Queue/scheduler:** `QUEUE_CONNECTION=sync` everywhere; no worker/scheduler. Don't add them.
- **Vite:** `public/hot` deleted; pages use built bundle. `npm run dev` recreates it. Vite only on IPv6 `[::1]:5173`.
- **Notifications:** Custom `notifikasis` table only. `via()` must return `[NotifikasiChannel::class]`. Add columns to `Notifikasi::$fillable`.
- **Array casts:** Model array casts `json_encode()` on assignment. Pass arrays, not JSON strings (double-encoding).
- **Time zone:** `UTC` in config — Indonesian local day differs (00:00–06:59 WIB = previous day). Don't assume local-day semantics.
- **Pest:** `tests/Pest.php` applies `TestCase` to Unit/Feature and `RefreshDatabase` globally to Feature. Don't re-add `uses(RefreshDatabase::class)`. Unit tests need opt-in DB. Helper names must be unique per file. Unit tests calling `PengumpulanTugasService::submit` with essays must `Bus::fake()` (sync AI can be slow). SQLite hides schema bugs vs MySQL.
- **Roles/routes:** Roles `operator|pengajar|pelajar` only (no `admin`). Route names `pengajar.*`/`pelajar.*`. Resource routes without `index/show` use `->except()`. `bootstrap/app.php` requires `expectsJson()` for API JSON responses.
- **Forms/components:** `x-form-input/select/textarea` don't forward `$attributes` (no `x-model` binding unless components updated). Alpine `x-collapse` needs plugin not installed. `@json()` not `Js::from()` for JSON payloads. AI tutor uses session-cookie auth.
- **Tugas/Kuis:** Essay type is `essai`. Resubmission without a new file preserves existing upload (`PengumpulanTugasService` keeps previous file). `KuisGeneratorService` normalizes answer keys (letters A-D or numeric). Materi utama vs pendukung are different concepts; don't mass-assign pivot data. **Timer per-siswa (CBT):** Guru can set `tugas.batas_jam` (hours). If set, students must click "Mulai Kerjakan" (`POST pelajar.tugas/{tugas}/mulai`) which creates/updates `pengumpulan_tugas` with `dimulai_pada` and `batas_kerjakan = now()->addHours(batas_jam)`. `PengumpulanTugasService::submit()` uses timer to mark `terlambat` (prioritizes timer over `deadline`); submit blocked until started if timer enabled. Timer fields: `tugas.batas_jam`, `pengumpulan_tugas.dimulai_pada`, `pengumpulan_tugas.batas_kerjakan`.
- **Chat API:** Session ownership enforced (`ChatSessionService::assertOwned/end/getSessionHistory` scoped by user). Sanctum auth required on all chat routes; `SendChatRequest` validates `uuid` + `max:2000`. Rate limiting applied via `throttle:chat` (30/min, 300/hour). `start/send` verify enrollment context via service; history only returns logs for the authenticated user's session.
- **ML/RF/SVR:** 4 features only. RF is comparison layer (labels from baseline), never retrains from itself. SVR uses grouped split by student. Training snapshot in `ml/dataset_latih.json` must match feature lists or training refused. `ml:train` must not be redeclared in `routes/console.php`. `prediksi_mendatang` keeps only latest forecast per student.
- **RAG/PDF:** Synchronous ingestion via `ProcessDocument::dispatchSync()`. `DocumentExtractorService` now enforces `services.pdf.timeout` with `proc_open`/`stream_select` (terminates on timeout). OCR/Tesseract/Pix2tex details matter. Kategori scoping via `kategori` on documents/chunks.
- **Remedial:** Single trigger via `PrediksiController::remedial()` per student (not mass loop). Global and per-pertemuan remedial have separate idempotency; `GenerateRemedialPertemuanAI` has `ShouldBeUnique`. Real-time triggers in controllers only (not in services called by tests). `MateriRemedial` needs all pertemuan columns fillable.

### Docker-Specific Gotchas

- **Production uses `QUEUE_CONNECTION=redis`** (not `sync`). The 3 queue workers (`queue-ai-soal`, `queue-pertemuan`, `queue-default`) and `scheduler` run as separate containers. `composer franken`/`dev` run workers inline — Docker runs them as services.
- **`APP_KEY` is mandatory** for production stack — container will fail without it. Generate via `php artisan key:generate --show` and put in `.env` or pass inline: `APP_KEY=base64:xxx docker compose up -d`.
- **Ollama GPU support** requires NVIDIA Container Toolkit and uncommenting `deploy.resources.reservations.devices` in `docker-compose.yml` (driver: nvidia). Without GPU, `qwen2.5:7b` runs on CPU (slow, offloads to RAM).
- **Python symlink:** Dockerfile installs Python 3.11 but symlinks as `python3.14` for `DocumentExtractorService` compatibility. `PYTHON_PATH=python3.14` in compose.
- **Volumes:** `./storage:/app/storage` and `./bootstrap/cache:/app/bootstrap/cache` are bind-mounted in all services. `node_modules` is a named volume for dev. Don't commit `storage/*` or `bootstrap/cache/*` to git.
- **Healthchecks:** Database, Redis, Ollama have healthchecks. App depends on them with `condition: service_healthy`. First startup takes 60-90s while Ollama pulls models.
- **FrankenPHP workers:** Production uses `php_server` directive in Caddyfile with `FRANKENPHP_NUM_WORKERS=2` / `FRANKENPHP_MAX_WORKERS=4`. Not the same as queue workers.
- **Dev profile:** `docker compose --profile dev up` starts `vite` + `app-dev` (with `QUEUE_CONNECTION=sync`, no separate queue containers). Vite HMR on port 5173 accessible from host.
- **Rebuild needed** after `composer.lock` or `package-lock.json` changes — `docker compose build --no-cache` before `up`.

## AI providers (`app/Services/AIProviderService.php`)

- **Guru/Siswa priority:** `sendLocalPreferred()` → Ollama #1 → Ollama #2 → Gemini. **Admin:** `sendOllama()` only. Raw `send()` starts with Gemini. Use `send()` where Gemini should be tried first (e.g. remedial), `sendLocalPreferred()` where local-first is wanted.
- Ollama chat timeout is **600 s**; `ChatService` calls `set_time_limit(0)`; `GEMINI_SHORT_TIMEOUT` is **8** in `.env` (config default 30).
- **Current `.env` models:** `OLLAMA_MODEL=qwen2.5:7b`, `..._FALLBACK_1=qwen2.5:1.5b`, `..._FALLBACK_2=simba-tutor-slim`. (`config/services.php` defaults differ: `simba-tutor` / `qwen2.5-coder:1.5b-base` / `qwen2.5:7b` — `.env` wins.)
- **Only instruct models.** A `-base` tag (`qwen2.5-coder:1.5b-base`) still answers `/api/chat` (no timeout) but degenerates into repeating "Tulis dalam bahasa Indonesia." — output exists but is incoherent and `isRefusal()` won't catch it. Overall `qwen2.5:7b` is more reliable for structured JSON than 1.5b despite exceeding 4 GB VRAM (offloads CPU/GPU). `qwen2.5:1.5b-instruct` is not a real tag (qwen2.5 is instruct-by-default); `ollama pull` for it fails 400 via REST.
- **Gemini model is `gemini-3.8-flash`** (`config/services.php`). Do not revert to `gemini-2.0-flash` (404 "no longer available"). `gemini-flash-latest` is a valid alias if the concrete model is ever deprecated.
- Custom `simba-tutor*` Ollama models are built from `Modelfile`, `Modelfile.slim`, `Modelfile.full` (`FROM qwen2.5:7b`, big Indonesian math/science symbol system prompts).
- **AI JSON parsing is deliberately tolerant and retried.** Central helper `AiJsonParser::decode()` / `arrayFrom()` / `objectFrom()` strips fences, finds the outermost balanced object **or** array (`balancedSlice`), and repairs quotes/commas/escapes. `RemedialTugasService` has its own `extractJson()` + `sejajarkanSkema()` (unwraps a top-level array, wraps a single `tujuan`/`soal` object into a list). Models frequently return `[{...}]`, prose after the fence, or a single object — a plain `\{...\}` regex is not enough. Generators retry up to 3× (`self::MAKS_PERCOBAAN`) with `Log::warning` per failure before giving up.
- **Reject junk instead of storing it.** `RemedialService::parseResponse()` returns `?array` and **never** falls back to raw text; unmatched output is logged and dropped. Watch for: short `ringkasan` (<250 chars), phrases like "jawaban harus"/"jangan lupa", empty `latihan`, NULL `bloom_tujuan`/`tugas_remedial`.
- **Parser drift exists.** `AiJsonParser` is the intended path, but three call sites still parse on their own: `RemedialService::parseResponse()` uses a **greedy** `/\{.*"ringkasan".*\}/s` (spans to the last `}` in the whole reply), and `PenilaianAIService` uses a single-attempt `\[[\s\S]*\]` with no retry. Prefer `AiJsonParser` when touching them; a model that prefixes prose can currently make both return empty/`null` silently. `RemedialService`'s prediksi path also has **no 3× retry** (unlike `RemedialTugasService`/`KuisGeneratorService`).

## RAG + PDF ingestion

- **Pipeline is synchronous:** upload PDF/TXT/MD/CSV → `ProcessDocument::dispatchSync()` → `DocumentService::chunkText` → embed → `document_chunks.embedding` (JSON) + `kategori`. FrankenPHP's threading keeps other users responsive. Don't switch to `dispatch()`/`dispatchAfterResponse()` without a strong reason.
- **Kategori scoping:** documents/chunks carry `kategori`; files save under `documents/{kategori}/`. `EmbeddingService::searchChunks($query, $k, $minScore, $kategori)` does cosine similarity in PHP with a `WHERE kategori = ?`. `ChatService::sendMessage()` pulls kategori from `materi->pertemuan->kelas->kategori`.
- **Multi-method PDF extraction** (`DocumentExtractorService` → `app/Python/extract_text.py`, Python 3.14 via `py -X utf8`): pdfplumber + PyMuPDF (text layer), Tesseract OCR (image-only pages), pix2tex LaTeX-OCR (formula images). A **mediator merges per page** (not elimination): text layer = body, `latex_ocr` formulas appended, OCR only fills image-only pages. Output has `pages_detail` + `sources`. Falls back to `smalot/pdfparser` if Python is unavailable.
  - pix2tex must be forced to GPU: `LatexOCR()` defaults `no_cuda=True`; `_get_latex_ocr()` computes `use_cuda = torch.cuda.is_available()` and passes `no_cuda: not use_cuda`. Runs only when the PDF has embedded image regions, capped at ≤40 pages / ≤60 regions (~3 min GPU vs ~8 min CPU for a 133-page formula-heavy PDF).
  - Tesseract at `C:\Program Files\Tesseract-OCR\tesseract.exe`; tessdata (ind+eng) in `storage/tessdata/`. Torch is the CUDA build (`2.9.1+cu126`, cp314).
  - Config: `services.pdf.python_path` (`PYTHON_PATH`), `services.pdf.timeout` (`PDF_EXTRACT_TIMEOUT`, default 600). **`services.pdf.timeout` is currently dead** — `DocumentExtractorService` stores it in `$timeout` but runs a blocking `exec()` with no timeout. A stalled pix2tex/torch process holds the synchronous request indefinitely; wrap in `proc_open`/a job timeout before trusting `PDF_EXTRACT_TIMEOUT`.
  - **Cost model is worse than "image-only pages":** `extract_tesseract()` OCRs the first ~50 pages of *every* PDF before the mediator decides which pages need it (text pages are then discarded), and the pix2tex whole-page fallback fires on every page where no formula was detected (not just image-only pages) whenever LaTeX-OCR is enabled. Digital-text PDFs therefore pay the OCR cost for nothing. OCR temp files are also fixed-name (`simba_ocr_{i}.png`) in the shared temp dir, so two concurrent ingestions can cross-contaminate.
  - `DocumentService::extractText()` / `extractFromDocxString()` are **unused** (`ProcessDocument` has its own extractors). If reused: `extractFromDocxString()` unlinks the temp file while the `ZipArchive` is still open, which throws on Windows.
- **Symbol annotation:** after extraction and before chunking, `ProcessDocument` calls `SymbolService::annotateFormulaPages($pages, $kategori)`. `FORMULA: {latex}` lines from pix2tex are matched against `symbols` (normalized LaTeX, threshold `services.symbols.formula_match_threshold` 0.9, min `formula_min_chars` 6, scoped by kategori) and an `[Simbol] {nama} | {formula} | {makna} (satuan: ...)` line is inserted. Those definitions then flow into `document_chunks` and RAG.

## Risk detection + next-meeting regression

- **4 academic parameters, computed in `MLService::computeAcademicFeatures` / `computeAllAcademicFeatures`** (the old 10 features are gone; these 4 are now the Random Forest input features): `rata_nilai` (combined graded kuis + tugas), `persen_terlambat` (late submissions ÷ submissions whose deadline passed), `persen_terlewat` (missed past-deadline tugas ÷ all past-deadline tugas), `nilai_keseluruhan` (points ÷ possible points × 100). Rows with `nilai IS NULL` are excluded from numerator **and** denominator. `computeAllAcademicFeatures()` enumerates students from `users WHERE role = 'pelajar'`, not from the feature table.
- **Deterministic risk score** = `PrediksiRisikoService` (Baseline Deviation Scoring): per (siswa, pertemuan) compute the 4 params, average the weighted (equal 0.25) distance from ideal `[rata_nilai 100, terlambat 0, terlewat 0, keseluruhan 100]` → `skor_penyimpangan` 0–100. Categories via `services.prediksi.ambang_aman` (20) / `ambang_pantau` (40): `aman` <20, `perlu_pantau` 20–<40, `berisiko_tinggi` ≥40. **Any null param → status `data_tidak_lengkap`, no score/category** (never label empty data "aman"). **Any non-numeric or out-of-range param (>100 / <0) → status `data_tidak_valid`, also no score/category** — the raw value is stored as evidence and is never silently clamped (`hitungSkor()` validates before scoring; `RENTANG_MIN`/`RENTANG_MAKS` are 0/100). `jalankan()` counts `lengkap` / `tidak_lengkap` / `tidak_valid` separately in its report.
  - `prediksi_risiko_pertemuan` stores per (siswa, pertemuan) (`unique(['siswa_id','pertemuan_id'])` + plain `index('siswa_id')`) plus `metode` (`baseline_deviation_scoring`) and `versi_konfigurasi` (`baseline_ideal_bobot_setara_v1`), so rows written by an older formula stay identifiable. `prediksi_ai` is a one-row-per-student **snapshot of the latest pertemuan** (`updateOrCreate(['siswa_id' => ...])`), written **only when status is `lengkap`** — otherwise the old row is left alone. The one-row-per-student unique index lives on **`prediksi_ai.siswa_id`** and **`prediksi_mendatang.siswa_id`**, *not* on `prediksi_risiko_pertemuan` (adding one there would break the per-meeting rows). A **schema-contract test** guards the real indexes because SQLite tolerates duplicate inserts.
  - One orchestrator: `PrediksiRisikoService::jalankan(bool $backfill = true)` (used by `PrediksiController::run()`/`retrain()` and the leftover `RunPrediksiJob`).
  - **Per-pertemuan denominators differ from the global ones**: `parameterPertemuan` uses all past-deadline tugas (not just submissions). Don't unify them.
  - **Run synchronously from HTTP, not queue** ("Jalankan Prediksi" → `PrediksiController::run()`, `set_time_limit(0)`). Measured 0.8–5.7 s at up to 4,000 students; the queue path uses PHP CLI `memory_limit=128M` and OOM'd at 4,000, while FrankenPHP HTTP has 512M. A regression test asserts `Queue::assertNotPushed(RunPrediksiJob::class)`.
  - "Latih Ulang" button is intentionally hidden; `retrain()` is equivalent to `run()`.
- **Random Forest classification = comparison layer only** (`KlasifikasiRisikoService`). RF is trained on the same 4 baseline params (`FITUR = MLService::FEATURES`, normalized 0–1) with **labels derived from the baseline rule** (`buildDataset()` only takes `status_data = lengkap` rows, so labels are exactly `PrediksiRisikoService`'s categories). Results go to a **separate column** `prediksi_risiko_pertemuan.kategori_risiko_rf` — the displayed reference category stays the baseline one. `train()` (50 trees, depth 12, grouped split per student) reports Accuracy / macro Precision / Recall / F1 + confusion matrix and writes `ml/rf_kategori_risiko.ser` + `ml/benchmark_rf_kategori_risiko.json`; `klasifikasiSemua()` re-labels every complete row in **one UPDATE per class** (not per row). Because the training labels come from the baseline, high accuracy means "RF reproduces the baseline rule", **not** that RF predicts real risk better — the UI must keep saying that (`rf_caveat`). RF output never becomes a label to retrain itself (`larangan_label` in concept v3). Callers: `ml:train` and `PrediksiController::jalankanPrediksi()` (batch); nothing runs RF per student row.
  - `Phpml\Classification\Ensemble\RandomForest` uses `random_int()` → training is **non-deterministic**; never assert exact predicted labels (assert membership in `LABELS`). `Bagging::train()` does `array_merge($this->samples, $samples)`, so a model instance must never be trained twice. The php-ml typo `setClassifer(string, array)` is the real API. `modelSesuaiFitur()` invalidates a model trained on an older feature list (`ml:train` re-run required) — same stale-artifact guard as the SVR.
- **Next-meeting regression** (`PrediksiMendatangService`, target `nilai_pertemuan_berikutnya`, 0–100): target comes from the **following pertemuan's** `fitur_siswa_history.rata_nilai` (row n → target row n+1), never from `skor_risiko` (that just re-learns the weighted formula). One pair per (siswa, kelas, pertemuan n→n+1); **split is grouped per student** (`splitGrouped()`) so no student appears in both train and test.
  - **Only candidate: `svr_linear`** (SVR LINEAR). OLS lost to collinearity (the 4 params are near-collinear; X'X is near-singular, R² once hit −6.4) and SVR RBF lost at small sample sizes. `buildCandidate()` still knows `linear`/`svr_rbf` (reflection-guarded test) — re-enable a candidate by adding a line to `KANDIDAT`, not by rewriting the switch.
  - Benchmark scaffolding is intentionally kept even with one candidate: compute split once, `is_finite` guard, write `benchmark_{target}.json` (`metode_pemilihan`, timestamps) + `svr_{target}.ser`/`_medians.json`. Failed candidates stay visible (status column); simplest working candidate is chosen when there's no test split.
  - **`Phpml\Regression\SVR::predict()` spawns a separate libsvm process (~47 ms each)** — never call it in a metric loop; use `predictBatch($model, $X)` (one process for all rows). `mae()/rmse()/r2()` take pre-computed predictions. `gamma` stays null (type is `?float`; don't pass `'scale'`). This fix took the suite 192 s → 7 s.
  - Guards: `minSamples=30` pairs + ≥3 unique students else `RuntimeException`. `r2` null when targets are identical. Normalize 0–100 → 0–1, median imputation (like `MLService`). Output clamped 0–100 because linear regression extrapolates.
  - `PrediksiMendatangService::predict()` writes to `prediksi_mendatang` (`horizon_hari=1`) as a side effect; returns a flat `{nilai_pertemuan_berikutnya}` or `['error' => ...]` (no `siap`/`alasan` — that wrapper key belongs to `PrediksiController::buildForecast()`).
  - **Each forecast carries its own metadata** (`prediksi_mendatang`): `pertemuan_sumber_id` (input row), `pertemuan_target_id` (the next meeting by `urutan`, **nullable** when the source is the frontier meeting), `nilai_ideal` (100.0), `persentase_meleset`, `status_data` (`lengkap`/`data_tidak_lengkap` from null features — imputation still happens, the flag just refuses to hide it), `model_versi` (`svr-Ymd\THis`, written into `benchmark_*.json` and read back via `versiModel()`), `nilai_aktual`, `mae_individual`. `PrediksiMendatangService::simpan()` **returns** that metadata so `predict()` can hand back exactly what was persisted (no second, divergent calculation) and also writes `prediksi_nilai_mendatang` onto the **source** `prediksi_risiko_pertemuan` row.
  - `persentaseMeleset($prediksi, $nilaiIdeal = 100)` = `abs(ideal − prediksi) / ideal × 100` (90→10, 75→25, 100→0); it is a **distance from the ideal**, **not** a prediction error — never present it as MAE. Throws when ideal ≤ 0.
  - `sinkronkanNilaiAktual()` backfills `nilai_aktual` + `mae_individual` for forecasts whose `pertemuan_target_id` now has a graded `fitur_siswa_history.rata_nilai`; idempotent (skips rows already in sync), and called by `ml:train` and `PrediksiController::jalankanPrediksi()`. `predict()` itself almost always leaves `nilai_aktual` null, because the source row is the student's frontier meeting and the target hasn't run yet.
  - `pertemuanBerikutnyaId()` uses the per-class `petaPertemuan()` map (one query, cached per `predictRows()` run and reset at its start) and the **opened** meetings only (`Pertemuan::dibuka()`).
  - The `nilai_ideal`/`persentase_meleset`/`status_data`/`model_versi`/`pertemuan_*` fields are surfaced by `PrediksiController::buildForecast()` and rendered on `pengajar.prediksi.show` (metadata grid + "Persentase meleset dari nilai ideal" card).
  - `ml:train` prints the benchmark via `barisBenchmark()`; read metrics from `$laporan['models'][$target]`, not top level. Regression failure only `warn`s, command still `SUCCESS`.
  - **Training data lives outside the DB as a snapshot** (`DatasetLatihService`, `ml/dataset_latih.json`). It stores exactly what `KlasifikasiRisikoService::buildDataset()` (samples already ÷100, labels) and `PrediksiMendatangService::buildDataset()` (raw 0–100 samples incl. nulls, targets, student/class ids) return, so `ml:train --dataset=...` reproduces training without the rows: `train(?array $dataset = null)` on both services takes the pre-built tuple. Both `train()` signatures are additive — callers without an argument still derive from the DB. The snapshot carries `rf.fitur`/`svr.fitur` and is **refused** when they differ from `KlasifikasiRisikoService::FITUR`/`FiturPertemuanService::fiturModel()` (training on shifted columns must never be silent). Tests: `tests/Feature/DatasetLatihTest.php`.
  - **`GroundTruthRisiko` is a scaffold only** — schema exists (label enum must match `berisiko_tinggi|perlu_pantau|aman`; `sumber` `guru|sistem`), no UI, no reader. Don't assume accuracy verification exists.
  - Tests: `tests/Feature/BenchmarkRegresiTest.php`, `tests/Feature/PrediksiMendatangTest.php` (incl. SVR metadata + `persentaseMeleset` cases 90→10 / 75→25 / 100→0 + `sinkronkanNilaiAktual`), `tests/Unit/Services/PrediksiRisikoServiceTest.php` (incl. `data_tidak_valid` + schema contract for the new columns/enum), `tests/Feature/KlasifikasiRisikoTest.php` (RF dataset/train/`klasifikasiSemua`/stale-model + `ml:train` flags), `tests/Feature/PrediksiSinkronTest.php`. `PrediksiShowTest` "model belum ada" must call `Storage::fake()` too, or it reads a real `storage/app/ml` artifact on a machine that ran `ml:train`. Note the RF `<details>` block: no RF benchmark (no `ml:train`) legitimately renders `rf_unavailable`, so **never assert the page never says a model is missing** — scope such assertions to the SVR message ("belum dilatih" lives only in `PrediksiMendatangService::predict()`'s error string; `rf_unavailable` deliberately says "belum tersedia").

## Remedial (`RemedialService`, `RemedialTugasService`)

- **Single trigger, per student:** `RemedialService::prosesSiswaBerisiko(?int $siswaId = null)`. The "Jalankan Prediksi" button no longer creates remedial; the guru uses `POST pengajar.prediksi.remedial/{siswa}` (`PrediksiController::remedial()`, synchronous, `set_time_limit(0)`) with badge "Perlu remedial" from `RemedialService::siswaButuhRemedial()`. Never copy the trigger loop elsewhere (`RemedialService::prosesSiswaBerisiko()` mass path exists for scripts/tinker only; a former polling loop produced 319 jobs).
- **Weak topics (`getWeakTopics`)** are computed two-tiered, never from fictitious columns: (1) per materi — combined `kuis_hasil.skor` (join `kuis.materi_id` + LEFT JOIN `kuis_materi`) and non-NULL `pengumpulan_tugas.nilai` (join `tugas.materi_id` + LEFT JOIN `tugas_materi`); (2) per pertemuan (always populated) — same via `pertemuan_id`. Each tier is computed in its own `try`. Rows without `materi_id` are **ignored, not scored 0**. Fallback: most-discussed materi in `chat_logs`, then `'Belum teridentifikasi'`. **Averaging is per-row** (`rataPerMateri()`): a materi that is both utama and pendukung in the same kuis counts once, and one score with many pivots yields multiple rows for the same utama materi — average all raw scores, not "average of averages".
- **Idempotency (global risk)** via `alasanDilewati(PrediksiAi): ?string`: skip if an unfinished (`status != 'selesai'`) `materi_remedial` exists for the student, or if `generated_at` is within `services.remedial.cooldown_hari` (default 7, `REMEDIAL_COOLDOWN_HARI`; `0` disables cooldown but **not** the unfinished check). Called **twice on purpose**: at dispatch in `prosesSiswaBerisiko()` **and** in `GenerateRemedialAI::handle()` (closes the double-click window before any row exists).
- **Per-pertemuan remedial (second source):** `prosesSiswaBerisiko()` also calls `prosesPertemuan()`, scanning each (siswa, pertemuan) and dispatching `GenerateRemedialPertemuanAI(siswaId, pertemuanId, skor)` when score `< services.remedial.ambang_pertemuan` (`REMEDIAL_AMBANG_PERTEMUAN`, default 75). Independent idempotency via `alasanDilewatiPertemuan()` (finish/cooldown) — global remedial does **not** block pertemuan remedial, and vice versa.
  - **Meeting score = only graded components:** average non-NULL `pengumpulan_tugas.nilai` and average `kuis_hasil.skor` for that (siswa, pertemuan); ungraded/missing work is **excluded from numerator and denominator**, never counted 0. Both present → `bobot_tugas` (0.8) · tugas + `bobot_kuis` (0.2) · kuis; only one present → use it as-is. Null score never triggers.
  - `GenerateRemedialPertemuanAI` implements `ShouldBeUnique` (+ `uniqueId()` `"{siswaId}-{pertemuanId}"`, `uniqueFor=3600`) — a **third** layer, because the DB guard can't see jobs still queued (repeated "Jalankan Prediksi" once stacked 89 jobs for ~45 candidates). Do not remove it. `generateForPertemuan()` retries 3× like `RemedialTugasService`.
  - Real-time triggers: `Siswa/KuisController::submit` → `periksaSetelahKuis()`, and `Guru/TugasController::nilaiSubmit` → `periksaSetelahNilaiTugas()`; both call `periksaPertemuan()`. **Never put triggers inside `PengumpulanTugasService::simpanNilai`/`submit`** — unit tests call those directly and `sync` would run real AI inline. Controllers are the correct boundary.
- **`GenerateRemedialAI::handle`** guards again, then creates a `MateriRemedial` + `RemedialTugasService::generateTugas()` (Bloom rubric, columns `bloom_tujuan`, `tugas_remedial`, `jawaban_remedial`, `hasil_remedial`, `bloom_tercapai`, `mastery_alasan`, `dinilai_at`; plus per-pertemuan columns `pertemuan_id`, `sumber` (`prediksi`|`pertemuan`), `skor_pertemuan`). **All three pertemuan columns must be in `MateriRemedial::$fillable`.** `generateTugas()` takes ~35–65 s/student — don't loop it synchronously in a request.
- Student submit: `pelajar.remedial.submit` resets prior results and dispatches `NilaiRemedialTugasAI`; `pelajar.remedial.reset` clears results to retry. Mastery verdict should be `true` only if average score ≥70 **and** most answers correct at the target level — but the service currently **trusts the model's `mastery.tercapai`** instead of recomputing it from `per_soal` (`RemedialTugasService::nilai`). The controller also sets `status = 'selesai'` **before** AI grading; `NilaiRemedialTugasAI` has `tries=1` and no `set_time_limit`, so a failed AI call leaves a "selesai" row with `hasil_remedial = null` that the teacher never sees as unfinished.
- **Guru lookup uses the `kelas_siswa` pivot directly** (`RemedialService::guruPengampu()`). Do **not** use `whereHas('kelas')->whereHas('siswa')` — nested `whereHas` over a `BelongsToMany` produces corrupt correlation (references `"kelas"."id"` with no `kelas` in the subquery FROM, and `where("user_id")` on a table whose column is `id`); SQLite silently returns empty, MySQL throws, so notifications never sent without visible errors. Student name column is `users.name`, not `nama`.
- Tests: `tests/Feature/RemedialTriggerTest.php`, `tests/Feature/RemedialPertemuanTest.php` (incl. 2 `ShouldBeUnique` guards), `tests/Unit/Services/RemedialServiceTest.php` (incl. schema contract + pivot-without-timestamps test — keep it).

## Bloom taxonomy (`BloomTaxonomyService`, single source = `database/data/bloom.json`)

- **No level constants in PHP** — everything goes through the service (`levels/label/shortLabel/metadata`, `valid`, `allowedRange/distribute/difficultyProfile`, `difficultyGuidance`, `rubric/classificationExamples/verbDisambiguationText`, `detect`/`confidence`/`decide`, `clampToRange`/`clampToDefaultRange`/`clampToSpan`, `enabled()`). Level is the **cognitive demand**, not keywords or difficulty. Difficulty→range: mudah C1–C2, sedang C2–C4, sulit C3–C5, essay/no difficulty C2–C4, remedial C1–C5 (no C6).
- **No migration** — `bloom` lives inside the `kuis.soal` / `tugas.soal` JSON (`TugasController::decodeSoal` passes it through). `services.bloom.enabled` (`BLOOM_ENABLED`) is a feature flag: when false, generators add no rubric and **no `bloom` key at all**.
- Controllers must pass `$bloomLevels = app(BloomTaxonomyService::class)->levels()` to `create()`/`edit()` (blade selectors depend on the variable). Builders (`kuis-builder.js`/`tugas-builder.js`) expose `bloomLevels` and keep the `bloom` key through edits/appends.
- **`lengkapiOtomatis()` fills levels for manually typed questions at save time** (in `TugasService::normalisasiSoal()` and `KuisController::soalDenganBloom()`). Existing valid C1–C6 levels are normalized but **not** overwritten; empty/invalid ones use `decide($pertanyaan, null, $kesulitan)`, then clamp. Do **not** check "already valid" via `valid()` — `valid($kode, $fallback='C2')` returns the fallback for empty input, so `has($this->valid(...))` is always true and nothing ever fills. Check the raw uppercased code. Do **not** inject this into `SoalTugasService` (pure array, no DB).

## Tugas / kuis (3-layer, essay grading, soal context)

- **Tugas is split across 3 layers:** front-end (`resources/views/guru|siswa/tugas/*` + `resources/js/pages/tugas-builder.js`) only renders and collects input; local normalization lives in `resources/js/pages/soal-tugas.js` (`normalisasiSoalPG`/`normalisasiSoalEsai`) and must not be re-implemented inline. Back-end (`app/Http/Controllers/Web/{Guru,Siswa}/TugasController.php`) only reads input, authorizes, calls a service, returns a response. Logic lives in `app/Services/Tugas/`: `SoalTugasService` (pure array: decode/encode, normalize PG/essay, `opsi`/`pilihan` fallback, bloom, answer index, AI-result lookup), `PengumpulanTugasService` (submit `updateOrCreate`, sanitize answers to int arrays, mark late via `Tugas::isLewatDeadline`, dispatch `PeriksaJawabanTugasAI` only when there is content; `simpanNilai(id=>nilai)`, `jadwalkanPemeriksaanAi`), `TugasService` (CRUD + pivot sync — **do not** `->withTimestamps()`, the pivot has no timestamps), `TugasPresenter` (display shapes).
- Task type essay is spelled **`essai`** (not `esai`) everywhere (enum, `Rule::in(['upload','pilihan_ganda','essai'])`, views, badges). Soal = array of `{pertanyaan, referensi?}`. Submitting dispatches `PeriksaJawabanTugasAI`; `PenilaianAIService::nilai()` stores `hasil_ai` + `nilai_ai` + `koreksi_ai_at`; AI failure just logs and leaves null ("menunggu pemeriksaan").
- **Resubmission overwrites the upload.** `PengumpulanTugasService::submit` is an `updateOrCreate` that writes `file => $file?->store(...)` unconditionally, so a second submit **without a new file** writes `file = NULL` and erases the previously uploaded artifact. Any fix must preserve the stored path when the request has no file (and must not add remedial triggers here — see the boundary rule above).
- **`KuisGeneratorService` answer key is `(int)` cast without letter support.** `(int) 'B'`/`'C'` → `0`, so an AI payload using letters silently points at option A; `'A'` "works" by accident. Options are also padding-filled to 4, so an out-of-range key can index an empty option. Normalize letters→index before storing.
- **Kuis schema:** builder/generator store `pilihan[]` + integer `jawaban`; the student view renders both `opsi` and `pilihan`; `Siswa/KuisController::submit` compares `(int)` so `"0" === 0` can't mis-grade.
- **AI generation for kuis/tugas** reuses `KuisGeneratorService` (`generate()` for PG, `generateEssai()` for essay) — there is no separate service. Endpoints `POST pengajar.kuis.generate` / `pengajar.tugas.generate` return JSON, authorize `create`, use `set_time_limit(0)`, and read optional keys with `?? null` (absent `topik` otherwise becomes an ErrorException → confusing 422).
- **Soal context selection:** teachers may draw on materi from **any pertemuan in their classes**, without moving the kuis/tugas. Request fields `konteks_pertemuan_ids` / `konteks_materi_ids` are declared once in `app/Http/Requests/Guru/Concerns/ValidatesKonteksSoal.php` (shared by both generate requests) and validated against ownership; `KuisGeneratorService::sumberKonteks($guruId, ?$kelasId)` feeds the checklists (create = current class only; edit = all classes). `buildMateriContext()`/`resolveSumber()` also re-filter ownership because the service is called outside FormRequests, and `materi_ids` is per-pertemuan (an unpicked pertemuan keeps all its materi). RAG quota is split evenly (`max(1500, max_chars / pertemuan_count)`). Frontend: `resources/js/pages/konteks-soal.js`, blade `components/konteks-soal-picker.blade.php`, used by all four `guru/{kuis,tugas}/{create,edit}` views; controllers must pass `$sumberKonteks`.
- **Materi attribution is 2 concepts, don't mix:** *materi utama* = nullable `kuis.materi_id`/`tugas.materi_id` (must belong to that item's own pertemuan); *materi pendukung* = `kuis_materi`/`tugas_materi` pivot (may be from another pertemuan of the teacher's class). Validation rules live once in `app/Http/Requests/Guru/Concerns/ValidatesMateriUtama.php`. `materi_ids` must not reach mass-assignment — call `$kuis->materiPendukung()->sync($request->materiPendukungIds($validated))`. UI: `components/materi-utama-select.blade.php`; builders store `materiUtama`/`materiPendukung` and clear `materiUtama` when `selectedPertemuan` changes. Edit views must pass both into `x-data`.

## Testing quirks

- Pest 4 (`composer test`), not PHPUnit directly. `phpunit.xml` overrides: `DB_CONNECTION=sqlite`, `DB_DATABASE=:memory:`, `QUEUE_CONNECTION=sync`, `SESSION_DRIVER=array`, `CACHE_STORE=array`, `WEB_SEARCH_ENABLED=false`.
- **SQLite hides schema bugs.** SQLite silently returns NULL/empty for nonexistent columns/tables; MySQL throws `SQLSTATE[42S22] Column not found` (or `no such table`). A query on a fictitious column can pass the whole suite and only explode on production MySQL. For schema-touching queries add a contract test using `Schema::getColumnListing()` / `Schema::getIndexes()` (see `tests/Unit/Services/RemedialServiceTest.php`).
- **The reverse trap also exists:** `fitur_siswa_history.tanggal` is `date` with cast `'tanggal' => 'date'`, so it stores `Y-m-d H:i:s`. Passing `now()->toDateString()` (a string) to a `where` brute-forces a new row under the `UNIQUE(siswa_id, pertemuan_id)` in SQLite while MySQL matches fine. Pass a Carbon object (`now()->startOfDay()`) instead.
- **Pest helper functions are global per file.** Two test files declaring the same function name fatal with `Cannot redeclare function` only when the full suite runs. Give every helper a topic-unique prefix (e.g. `remedialBuatPertemuan`, `konteksUntuk`, `remPert`, `bm-*`), never a generic name already used elsewhere.
- **Unit tests that call `PengumpulanTugasService::submit` with essay answers must `Bus::fake()`** — with `QUEUE_CONNECTION=sync` the AI job runs inline and hits real AI (~30 s/test; one file went 174 s, pushing `composer test` past a 300 s timeout). With the fake it dropped to 3 s.
- **`tests/Pest.php` already applies `TestCase` to both `Unit` and `Feature`, and `RefreshDatabase` globally to `Feature`** (not commented out). Do **not** re-add `uses(RefreshDatabase::class)` in Feature files — it is redundant; several tests (`TugasEssaiAiTest`, `TugasAiGenerateTest`, `PrediksiSinkronTest`) depend on the global trait. Unit tests have no DB unless they opt in.

## Known open defects (verified by full-code review, Oct 2026)

These are real and reproducible; do not "fix" them by accident while doing an unrelated change, and do not build features that assume they are solved.

**High**
- `Guru\TugasController::nilaiSubmit` → `RemedialService::periksaSetelahNilaiTugas()` loops over **every** graded student on that tugas and dispatches `GenerateRemedialPertemuanAI`; under `sync` each dispatch runs 35–65 s of AI inline, with **no `set_time_limit(0)`**. Grading a class of 20–30 can hold one POST for 10–30+ minutes. The per-student `PrediksiController::remedial()` path is the intended shape.
- `ChatSessionService` never scopes `sesi_id` to the caller, and `Api\ChatController::end/history` authorize authentication only. Anyone with a leaked UUID can read another student's transcript (`GET api/chat/history`) or close their session (which also summarizes the victim's logs). `start/send` likewise never verify enrollment in `pertemuan_id`; `ChatService::getUserHistory()` returns the **user's** last 10 messages across *all* sessions, not the current one.
- `PengumpulanTugasService::submit` clears `pengumpulan.file` on any resubmission without a new upload (see Tugas section).
- `KuisGeneratorService` casts `jawaban` with `(int)` only, so letter keys (`"B"`/`"C"`) silently mean option 0 (see Tugas/kuis section).
- `DocumentExtractorService` ignores `services.pdf.timeout` and blocks on `exec()`; Tesseract OCRs every page up to the cap even for digital-text PDFs (see RAG/PDF section).

**Medium**
- `Siswa\KuisController::show/submit/hasil` check enrollment + `pertemuan.dibuka` only. `is_aktif`, `tanggal_mulai` and `tanggal_selesai` are enforced in `index()` but **not** on the direct-URL paths, so a deactivated/expired kuis can still be submitted.
- `UpdateKuisRequest`/`UpdateTugasRequest`/`UpdateMateriRequest` validate `kelas_id`/`pertemuan_id` with `exists:` only. A teacher can re-parent their own kuis/tugas/materi into **another teacher's** class (authorization is checked on the old record), and `pertemuan_id` is never checked against `kelas_id`.
- `Siswa\KelasController::available()` search uses an ungrouped `orWhere` after `status='dibuka'`/`aturan_kelayakan`, so a matching `kode_kelas` leaks closed or ineligible classes; `enroll()` bypasses `KelasPolicy::enroll()` and ignores `kelas.status`.
- `Admin\UserController::verify/reject` writes `verified_by`/`verified_at`, which are not fillable (see Roles section).
- `ChatService` persists the **augmented** prompt (`Dokumen pembelajaran…`, system context) as the `user` message, then passes the raw message again plus that history row to the provider — context accumulates multiplicatively over turns and the transcript/history API shows prompt scaffolding instead of what the student typed.
- `RemedialController::submit` marks `status='selesai'` before grading; `NilaiRemedialTugasAI` is `tries=1` with no `set_time_limit` (see Remedial section). `RemedialTugasService::nilai` trusts `mastery.tercapai` instead of recomputing it.
- `AktivitasService::catatDurasi` is a read-modify-write without a lock; two tabs or the 30 s timer + `pagehide` can lose updates to `metadata.durasi_menit`.
- `EmbeddingService`: `env('EMBEDDING_PROVIDER')` breaks under `config:cache` (falls back to ollama); `whereRaw('JSON_LENGTH(...)')` is MySQL-only (SQLite tests diverge); `cosineSimilarity` truncates to the shorter vector, so mixing embedding dimensions scores garbage silently; `searchChunks` lazily loads `document.materi` per chunk (N+1).
- `PrediksiRisikoService::jalankan()` wraps the whole student loop in one `try/catch(Throwable)` and returns a normal report — a single bad student aborts the remaining updates but the UI says the run succeeded. `FiturPertemuanService::backfill()` recomputes **every** (siswa, pertemuan) pair with no "already up to date" check and writes each row, so every run rewrites the whole `fitur_siswa_history` table (the main cost behind the documented 0.8–5.7 s measurement).
- `RemedialService::parseResponse()` greedy regex + no retry on the prediksi path (see AI providers section).

**Low**
- `MateriObserver::SUPPORTED_TYPES` accepts `doc`/`ppt`/`xls`, but `ProcessDocument` rejects `.doc` and has no branch for `ppt`/`xls` → materi row created, document `failed`, no chunks. `pptx`/`xlsx` are supported.
- `WebSearchService` disables TLS verification (`verify => false`) for DuckDuckGo and returns redirect URLs stripped of tags only; that text is injected into the tutor prompt.
- `RemedialTugasService`/`PenilaianAIService` trust model-returned mastery/averages (see above); `PenilaianAIService` parses JSON with a single-attempt regex.
- `DatasetLatihService` writes the snapshot non-atomically; a crash mid-write leaves a truncated `dataset_latih.json` and `ml:train --dataset` then refuses to train.
- `config/services.php` defaults `rag.chunk_overlap` to **100** while `ProcessDocument`/`DocumentService` default to **200** — same file, different chunk boundaries depending on path.
- `ImportRequest` accepts `.xls`/`.txt` but `UsersImport` treats anything not `xlsx` as CSV; row `role` is unvalidated (bad value hits the DB CHECK).
- `HomeController::show` allows `published_at = null` berita (NULL > now is false) while `index()` hides them.
- `PrediksiMendatangService::simpan()` is `updateOrCreate(['siswa_id'])`, so **`prediksi_mendatang` keeps only each student's latest forecast**. `sinkronkanNilaiAktual()` can only backfill the surviving row; a forecast for an earlier target is overwritten once the student has a newer source meeting. `predict()` is only called from `PrediksiController::show` (per student) and `latih:seed-data`, not from the batch button.
- `resources/js/pages/trial.js` is imported by `app.js` but has no route/controller; `welcome.js` can never load (no `.reveal` element exists).
- `prose`/`prose-sm`/`dark:prose-invert` are used in berita/remedial views but `@tailwindcss/typography` is not installed.
- Several small-text classes lack dark pairs (`text-red-600`, `text-green-700` on `slate-800/900`), e.g. the form components, `alert`, `pengajar/prediksi/show`, `siswa/kuis/hasil`.
